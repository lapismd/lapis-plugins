# Distribution and Releases

The Source Editor, Markdown and Graph dependency repair accepts Design Core
`^0.4.0 || ^0.5.1`. Their independent patch release intent is recorded; local
Desktop acceptance does not publish packages, sign production artifacts or
advance release gates.

Search accepts Design Core 0.4 and 0.5 through portable semver ranges; its
locked 0.4 graph and source/package ownership remain unchanged. Local 0.5
consumer acceptance is recorded in `spec/records/2026-10-19-search-empty-results.md`.

The independent Bases 0.1.4 candidate includes pending result-limit contrast and
picker accessibility fixes on the existing published dependency graph. It can
ship ahead of the Design Core 0.4.0 consumer refresh to avoid a framework/plugin
release dependency cycle. Publication still requires explicit approval.

The private persistent Sync review host retains the Notes application's Turso
0.7.2 compatibility pair: `@napi-rs/wasm-runtime@1.0.7` resolves both emnapi core
and runtime to registry version 1.8.1. This confines the compatibility pins to
that driver chain; other native/WASM runtimes retain their existing resolutions.

Bases carries independent patch release intent for result-limit label contrast.
The component retains Design Core typography and color; the CI repair does not
activate package publication or change plugin host contracts.

First-party plugin packages, private Sync Settings and the shared development
host require published Design Core `^0.4.0`, including prepared browser CSS and
bundled fonts alongside controlled header actions and compact file inputs.
Both the shared and parked Sync lockfiles resolve registry packages with local
pnpm hooks disabled; this does not select Sync for publication.

The Design Core refresh patch also restores Bases picker input/list links and
accessible property-action names. Existing patch release intent includes this
repair; package publication still requires separate approval.

Lapis Sync remains private and parked under LP-SPEC-049. Its explicit shared
Storybook entry and media-only registry catalog permit UI review without
installation, publication or registry dispatch. Direct package checks qualify
its engine and UI; Deno runtime integration remains pending.

The shared CI toolchain is `lapis-ci:2026.10.14.1`, pinned by immutable digest.
Its checksum-verified GitHub CLI 2.102.0 supports package release records and
registry dispatch. The lockfile-specific dependency image must be rebuilt over
that base before the production release workflow uses it.

The static release uses published API, UI and File Explorer 0.1.2, Workspace
0.2.0 and Language Service 0.1.1 through the shared package catalog. Independently versioned
plugin candidates must retain matching npm, runtime manifest and changelog
coordinates. Slides remains an initial 0.1.0 candidate; Community stays parked.

The final static candidate prepares AI 0.1.5, History 0.1.4 and Markdown 0.1.6
from their independent Changesets. AI's Markdown peer and development edges
advance together to `^0.1.6`; unchanged plugin versions retain their existing
release coordinates. Full package, Storybook, pack and deterministic archive
qualification runs on the exact version PR in CI before release approval.

Dependency acceptance now uses published Design Core `0.3.2` and Mira `0.0.4` through portable npm ranges. Source ownership and public contracts remain
unchanged; local overrides for these released packages are retired.

Markdown's Mira floor includes the upstream pending-overlay teardown repair.
The frozen graph resolves Bits UI 2.19.5 through that released provider, while
retaining its already qualified Link Preview selection cleanup patch.

First-party packages and their shared development host resolve Design Core from
the current published npm semver range recorded in manifests and the committed
lockfile.
The Sync Settings review uses released Design Core 0.3.4 for readable label
columns and full-width action feedback beneath each setting row.

The Search checkpoint repair carries independent patch release intent and
requires the API's filtered metadata fingerprint contract. Release preparation
must establish that prerequisite version before setting the plugin API floor
and qualifying portable consumers. The static publication gate is independent
of the deferred Nostr release and registry-head renewal gates.

Signed runtime bundles share the allowlisted CodeMirror editor and Lezer core
modules with the host. Plugin-local language grammars remain bundled. Host import
maps and signed shared-dependency metadata bind these singleton contracts, whose
package roots are portable npm peers.

Development checks must resolve compatible host peers consistently across
plugins that exchange API classes through public exports. The frozen lockfile
must deduplicate compatible CodeMirror peer versions; a type cast or alias is
not a substitute for a coherent dependency graph. Audit exceptions for
unpatched advisories must record dependency paths, input exposure and removal
conditions in `spec/records` alongside their CVE entries.

The shared catalog and private Sync development graph consume released UI
0.1.3, whose retained runtime imports are declared as runtime dependencies.
The registry lockfile reconciles compatible API and editor peer contexts across
plugin development checks; public plugin peer ranges remain unchanged.

The shared Storybook font gate must wait for actual catalog font faces within a
fixed timeout, including faces registered during story startup. It must reject
fallback-only availability, failed downloads and missing font tokens. Every
resolved Bits UI version must retain its qualified lifecycle patch and locked
hash until an upstream release fixes the teardown defect; the user approved the
scoped 2.19.5 patch exception for this qualification.

Plugin behavior corrections use an independent package patch changeset and
retain focused owning-package checks plus real consumer Storybook acceptance as
release evidence. Preparing that candidate does not authorize npm publication,
public release assets, or registry dispatch.
Registry media refinement MUST preserve the fixed story IDs and output
dimensions while strengthening each story's final-state assertions. Shared
fixtures MAY stabilize source-specific diagnostics after the real provider has
produced them, but MUST keep the editor and Problems collections consistent.
Applying that changeset to a release candidate MUST update the selected package
metadata and each owning plugin chapter together, then pass the complete
tarball, rootless-payload, portable-proof, and clean-consumer preparation gate
before approval.

Shared Storybook imports API's public `build/vite` helper for prebuilt Turso
client and worker modules. The helper is shipped by its owning package; consumers
do not copy its transform or rewrite dependency files. Preview never starts
`lapis-ai-controller`. When `LAPIS_AGENT_RUNTIME_URL` and
`LAPIS_AGENT_RUNTIME_TOKEN` are set, it registers the same thin controller
connection bridge Notes uses so live stories are not silently Fake. Local
controller migration acceptance uses documented temporary tarballs until their
approved registry releases.
The AI Chat catalog also exercises the two OpenCode harness choices through its public composer while keeping the Storybook execution fixture deterministic.

Nostr release publication and head renewal remain deferred behind `NOSTR_RELEASE_ENABLED`. Static publication uses the separate `STATIC_RELEASE_ENABLED` switch, the existing `release.yml` trusted-publisher identity, and the protected first-publication gate.

Compiled renderer archives use `svelte/renderer/<compiler-version>` host contracts
for Svelte and its declared browser runtime exports. The host provides these
entries through its own Svelte module graph. Original private host specifiers stay
private; compiler-version drift and unsupported renderer contracts fail closed.
Npm packages keep ordinary Svelte imports and portable peers.

Browser runtime builds replace `process.env.NODE_ENV` with the production
