## Host remote service contract

The public repository service MAY provide remote management alongside the legacy
backup-only remote port. It MUST expose path-free snapshots, explicit target
selection, advertised transport capabilities and opaque credential references.
Every connection or transfer command MUST carry the expected native configuration
revision. Push execution MUST identify a prior native review; uncertain results
MUST retain their request identity for observation rather than replay.

The shared presentation controller MUST NOT retry failed mutations automatically,
transfer after saving, persist tokens, or accept late responses after disposal.
Pending transfers MUST project progress only to their selected target, including
new subscribers. After a mutation fails, one secret-free status read MAY expose
its retained native request; a failed status read MUST preserve the original
failure and last observation. This recovery never retries a mutation.
Connection tests are explicit reachability/authentication checks without
publication. Host implementations own credential custody and endpoint admission;
presentation validation cannot authorize transport.

Working-copy frame parsing MUST preserve its native history source for subsequent
navigation. Legacy frames without an explicit source retain backup semantics;
unknown or null sources refuse. Dismissing a push review MUST suppress that same
target/review identity through later observations in the current controller
session, while a new native review remains visible. A retained review MUST NOT
enable publication when the host withdraws push capability, including locked
credential storage; Cancel remains available when no push is running.

Registry qualification for optional-state projection consumes API `^0.6.2` from
npm. The temporary built API archive is retired after publication; hosted
multiple-head recovery stories retain their exact first-click assertions.

## Native remote presentation adoption

When a host supplies `services.remotes`, the enabled Repository History plugin
owns one native observation controller and one push-review host. Retained reviews
MUST NOT open automatically during shell startup. An explicit review action
selects its target; native settings, JJ Log, Op Log and the working-copy header
share those actions. Footer hiding or settings closure MUST NOT dispose that
controller or prevent review. Plugin teardown fences late replies and disposes
its App-document portal without stopping already accepted native work.

Both log headers show fetch/push only for their configured source. The existing
working-copy details and split Git footer select the working-copy source, retain
